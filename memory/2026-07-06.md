### Correções implementadas hoje

#### 1. Classificador de intenção — respostas inválidas (`V`, `GER`, `PRO`, etc.)
- **Arquivo:** `agents/orchestrator.py`
- **Causa:** `.upper()` sem sanitização — `"VENDAS\n"`, `"VENDAS."` não passavam na validação `in VALID_INTENTS`
- **Fix:** `re.sub(r'[^A-Z]', '', raw.upper().strip().split()[0])` — pega só a primeira palavra, remove não-letras
- Histórico do classificador: 5 trocas → 3, truncadas a 200 chars; contexto do cliente truncado a 300 chars
- `max_tokens` do classificador: 10 → 20

#### 2. Gemini caindo para Claude (MAX_TOKENS em classificações)
- Prompt do classificador enxugado (removeu preâmbulo desnecessário)
- Opções de intent em linhas separadas (modelos respondem melhor a listas verticais)

#### 3. Flora se apresentando em conversas já iniciadas (caso Iraci — (47) 9981-6366)
- **Arquivo:** `agents/base.py` — `_get_system_prompt()`
- **Fix:** verifica `has_history` via `memory.get_history(phone, limit=1)` — se tem histórico, injeta contexto "NÃO se apresente"
- Prioridade: histórico local > Shopify > padrão conservador (não apresenta)

#### 4. Saudação repetida no mesmo dia
- **Arquivo:** `memory/shared_memory.py` — novo método `greeted_today(phone)`
- Consulta SQLite: mensagens `role='assistant'` das últimas 24h, regex `bom dia|boa tarde|boa noite|olá|oi`
- Injetado em `_get_system_prompt()`: se já saudou hoje → instrução explícita para não repetir

#### 5. Limite de emojis — 3 por conversa
- **Arquivos:** todos os 7 prompts em `prompt/prompts.py`
- **Arquivo:** `memory/shared_memory.py` — novo método `count_emojis_sent(phone)`
- **Arquivo:** `agents/base.py` — injeta dinamicamente no prompt quantos emojis restam
- Se `emoji_remaining == 0` → instrução "NÃO use nenhum emoji nesta resposta"

#### 6. Mensagens cortadas — MAX_TOKENS na resposta (caso (17) 99609-5930)
- **Causa:** `BaseAgent.MAX_TOKENS = 1024` insuficiente para respostas de produto
- **Fix:** `BaseAgent.MAX_TOKENS`: 1024 → **2048**; `ProdutoAgent.MAX_TOKENS`: **3000**
- Mensagem truncada reenviada manualmente para a cliente; banco corrigido (id=3495)

#### 7. Gemini entregando resposta truncada silenciosamente
- **Arquivo:** `llm/client.py` — `_call_gemini()`
- **Fix:** detecta `finish_reason == MAX_TOKENS` + `max_tokens >= 200` → trata como falha → retry → fallback Claude
- Limiar 200 evita falso positivo em classificadores (max_tokens=20 é comportamento normal)

- Referência: conversa do Eros (5519995994481) como padrão de envio correto
